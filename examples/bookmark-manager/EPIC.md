# EPIC: DEMO-0001 — Bookmark Manager

## Context

We need a full-stack bookmark manager — a web app where users can save, tag,
search, and organize web bookmarks. The app should be self-contained with no
external dependencies (no database server, no auth service). This serves as
a demo of AID orchestration that produces a real, usable application.

Tech stack: FastAPI (backend) + React/TypeScript (frontend) + SQLite (storage).

## Goal

When complete, a user can:
1. Add bookmarks (URL, title, description, tags)
2. Browse bookmarks in a card-based grid layout
3. Filter by tags and search by title/description
4. Edit and delete existing bookmarks
5. Auto-fetch page title and favicon from URL
6. See bookmark count per tag in a sidebar

The app runs locally with `uvicorn` (backend) and `npm run dev` (frontend).

- No external database — SQLite file in `data/bookmarks.db`

## Acceptance Criteria

- [ ] POST /api/v1/bookmarks creates bookmark with URL, title, description, tags
- [ ] GET /api/v1/bookmarks returns paginated list (default 20)
- [ ] GET /api/v1/bookmarks?tag=python filters by tag
- [ ] GET /api/v1/bookmarks?q=search searches title and description
- [ ] GET /api/v1/bookmarks/{id} returns single bookmark
- [ ] PATCH /api/v1/bookmarks/{id} updates bookmark fields
- [ ] DELETE /api/v1/bookmarks/{id} removes bookmark
- [ ] GET /api/v1/tags returns all tags with bookmark counts
- [ ] Auto-fetch: when URL is submitted, title is fetched if not provided
- [ ] BookmarkGrid renders cards with title, URL, tags, favicon
- [ ] TagSidebar shows tag list with counts, click filters grid
- [ ] SearchBar filters bookmarks in real-time
- [ ] BookmarkForm validates URL format before submit
- [ ] Unit tests cover CRUD operations and edge cases
- [ ] API docs page accessible and complete

## Notes

- SQLite is chosen for zero-config setup. No migrations needed — create tables on startup.
- URL title fetching should have a timeout (3s) and graceful fallback (use URL as title).
- Tags are stored as a separate table with many-to-many relationship.
- Frontend should use `fetch()` directly — no state management library needed for this scope.
- Favicon: use `https://www.google.com/s2/favicons?domain={domain}` for simplicity.
