# Quality Gates - Instructions

**Skill:** quality-gates
**Dependencies:** agent-core

---

## TL;DR - MUST Rules

1. **RUN all 6 gates** before EVERY commit (no exceptions)
2. **Required gate fails** → FSM transitions to ESCALATION → PM decision required
3. **ALL required gates pass** → Curator hook → FSM: DONE
4. **Gates run via `aid-run-gates.sh`** — not inline LLM execution
5. **Gate config** lives in `.aid-o/config/execution.yaml`

---

## When to Run

**Before EVERY commit** that includes code, config, refactoring, bug fixes, or features.

```
Code ready → FSM: GATES → aid-run-gates.sh run-all → ALL PASS → FSM: DONE
                                                     → REQUIRED FAIL → FSM: ESCALATION
```

**Quick reference card:** See `checklist.md`

---

## How Gates Run in v2

1. FSM transitions to GATES state (pipeline.md §5)
2. `aid-run-gates.sh run-all execution.yaml {epic_id} {run_id}` executes all gates
3. Each gate: runs command → logs to timeline.jsonl → returns pass/fail
4. Required gate fails after retries → FSM: ESCALATION → PM decision
5. All gates pass → Curator hook → FSM: DONE

Gates are configured per-project in `.aid-o/config/execution.yaml`.
Default gates: tests_pass, lint_pass, build_pass, security_scan, scope_check.
Optional: docs_updated (enabled by default, non-blocking).

---

## The 6 Quality Gates

### Gate 1: tests_pass — CRITICAL

**Purpose:** Verify no regressions introduced by the change.
**Command:** from `execution.yaml` → `tests_pass.command`
**Required:** true
**Max retries:** 2
**Pass:** exit 0
**Fail:** exit ≠ 0 → FSM: ESCALATION if required=true and retries exhausted

---

### Gate 2: lint_pass — CRITICAL

**Purpose:** Enforce code style and formatting consistency.
**Command:** from `execution.yaml` → `lint_pass.command`
**Required:** true
**Max retries:** 0 (auto-fix formatters run in pre-commit; no retry loop needed)
**Pass:** exit 0
**Fail:** exit ≠ 0 → FSM: ESCALATION

---

### Gate 3: build_pass — CRITICAL

**Purpose:** Verify the project compiles and builds successfully.
**Command:** from `execution.yaml` → `build_pass.command`
**Required:** true
**Max retries:** 1
**Pass:** exit 0
**Fail:** exit ≠ 0 → FSM: ESCALATION after retries exhausted

---

### Gate 4: security_scan — HIGH

**Purpose:** Detect known vulnerabilities in dependencies and code.
**Command:** from `execution.yaml` → `security_scan.command` (default: `npm audit` / `bandit`)
**Required:** true
**Max retries:** 2
**Pass:** exit 0 (no high/critical vulnerabilities)
**Fail:** exit ≠ 0 → FSM: ESCALATION

---

### Gate 5: docs_updated — MEDIUM

**Purpose:** Keep documentation synchronized with code changes.
**Command:** from `execution.yaml` → `docs_updated.command`
**Required:** false (advisory — non-blocking, logs warning on failure)
**Max retries:** 1
**Pass:** exit 0
**Fail:** exit ≠ 0 → logged to timeline.jsonl as WARNING, does not block FSM: DONE

Documentation impact reference (for docs-check.sh implementation):

| Code Change | Usually Affects |
|-------------|-----------------|
| Database models | ERD, schema docs |
| API endpoints | API docs, integration guides |
| Core business logic | System overview, architecture |
| UI components | Component docs, UI guide |
| Configuration | Setup guide, deployment docs |
| Any `feat:` or `fix:` | CHANGELOG.md |
| Breaking changes | Migration guide |

See `documentation-protocol` skill for full documentation rules.

---

### Gate 6: scope_check — HIGH

**Purpose:** Verify the commit scope matches the EPIC specification and does not introduce unplanned changes.
**Command:** `bash scripts/gates/scope-check.sh`
**Required:** true
**Max retries:** 0 (deterministic result — scope either matches or does not)
**Pass:** exit 0 (staged changes within declared EPIC scope)
**Fail:** exit ≠ 0 → FSM: ESCALATION

The script reads the active EPIC spec and compares against `git diff --cached --name-only`.

## Gate Execution — `aid-run-gates.sh`

The gates are executed by `scripts/aid-run-gates.sh`, not by the LLM directly.

```bash
# Run all gates for an EPIC run
aid-run-gates.sh run-all .aid-o/config/execution.yaml {epic_id} {run_id}

# Run a single gate (for debugging)
aid-run-gates.sh run-gate tests_pass .aid-o/config/execution.yaml {epic_id} {run_id}
```

Each gate execution:
1. Reads gate config from `execution.yaml`
2. Runs the configured command in a subprocess
3. Captures stdout/stderr + exit code
4. Appends structured entry to `.aid-o/work/timeline.jsonl`
5. Returns `pass` (exit 0) or `fail` (exit ≠ 0)

---

## Configuration

Gates are configured per-project in `.aid-o/config/execution.yaml` (generated by `/aid-setup`, editable by PM):

```yaml
# .aid-o/config/execution.yaml

gates:
  tests_pass:
    command: "pytest tests/ -v"
    required: true
    max_retries: 2

  lint_pass:
    command: "ruff check . && npx eslint src/"
    required: true
    max_retries: 0

  build_pass:
    command: "npx vite build"
    required: true
    max_retries: 1

  security_scan:
    command: "npm audit --audit-level=high"
    required: true
    max_retries: 2

  docs_updated:
    command: "bash scripts/gates/docs-check.sh"
    required: false
    max_retries: 1

  scope_check:
    command: "bash scripts/gates/scope-check.sh"
    required: true
    max_retries: 0
```
