# /aid-plan-epic

Parse an EPIC or Plan file and generate a Plan JSON, progress tracker, and run file that [`/aid-run-epic`](./aid-run-epic) will follow. This command is the unified entry point to orchestration — it accepts both EPIC files (standard path) and Plan files (auto-converts the plan to an EPIC first).

## Usage

```bash
/aid-plan-epic <path-to-epic-or-plan-file>
```

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `path` | string | No | Path to the EPIC or Plan file. If omitted, lists files from both `.aid-o/02-epics/` and `.aid-o/01-plans/` for selection. |

## Prerequisites

- `.aid-o/` workspace must exist (run [`/aid-init`](./aid-init) first)
- Input file must be an EPIC (preferred) or a Plan (auto-converted to EPIC)

## Examples

```bash
# Standard EPIC input
/aid-plan-epic .aid-o/02-epics/E-005-1_1-user-auth.md

# Plan input — auto-generates EPIC, then produces Plan JSON
/aid-plan-epic .aid-o/01-plans/P005-user-auth.md

# If only one EPIC exists, it is auto-selected
/aid-plan-epic
```

## How It Works

### Input Format Detection

The command detects whether the file is an EPIC or a Plan using frontmatter (`type: plan`), heading patterns (`# Plan:` vs `# EPIC:`), and section fingerprinting (`## DoD Gates` signals EPIC format). Ambiguous files prompt you to clarify.

### Plan-to-EPIC Conversion (Plan Input)

When a Plan file is provided:

1. An EPIC is auto-generated using the EPIC Subagent Template from the brainstorming skill
2. The generated EPIC is shown to you for review (Goal, Scope, Steps, Gates)
3. You approve, reject, or edit before plan generation proceeds

### Plan JSON Generation

For EPIC input (or after Plan conversion), the command:

1. **Validates** required EPIC sections (Goal, Scope, Constraints, DoD Gates, Acceptance Criteria)
2. **Builds the dependency graph** — topological sort, cycle detection, parallel group assignment
3. **Generates analysis groups** — auto-triggers for security-relevant steps, high-complexity steps, database changes, and API contract changes
4. **Produces Plan JSON** with steps, dependencies, parallel groups, analysis groups, gates, and budget
5. **Self-validates** the JSON (unique IDs, valid roles, no circular dependencies, valid gate names)
6. **Saves** plan.json, plan_progress.json, and a copy of the EPIC to the evidence directory
7. **Generates a run file** — a human-readable operational document for the run

### Default Step Ordering

When an EPIC does not specify a custom order, the planner uses these defaults:

1. `architect` — always first (contracts before code)
2. `domain` — after architect (needs contracts)
3. `backend` + `frontend` — in parallel (both depend on contracts)
4. `qa` + `security` + `observability` — in parallel (all depend on implementation)
5. `docs` — after implementation
6. `release` — last (needs all gates to pass)

EPICs can override this order explicitly.

## Output Files

All files are saved under `.aid-o/04-engine/evidence/{epic_id}/{run_id}/`:

| File | Description |
|------|-------------|
| `plan.json` | Structured execution plan with steps, dependencies, and gates |
| `plan_progress.json` | Progress tracker (initialized with all steps in `pending` state) |
| `epic_input.md` | Copy of the EPIC file for evidence |
| `.aid-o/04-engine/runs/{run_id}-{topic}.md` | Human-readable run file |

## After Planning

After the plan is generated, the command asks:

```text
Ready to execute?
  Want to run this EPIC now?  → /aid-run-epic {epic_id}
  Review plan first?          → open .aid-o/04-engine/evidence/{epic_id}/{run_id}/plan.json
  Run a single step?          → /aid-run-epic {epic_id} step_1_architect
```

## Notes

- The original EPIC file is **never modified** — it is only copied to the evidence directory
- If a Plan JSON already exists for the EPIC, you are asked whether to create a new version
- Budget defaults: `max_llm_cost_usd: 50`, `max_retries_per_gate: 3` (unless the EPIC specifies otherwise)
- The generated plan is a proposal — you review it in [`/aid-run-epic`](./aid-run-epic) at the PLAN_REVIEW checkpoint before execution begins
