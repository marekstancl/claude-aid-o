# Agent Core

The foundational skill that establishes the behavioral rules every AID agent must follow. It defines how agents orient themselves at the start of each run, how to select the right role and mindset for a task, and what non-negotiable rules govern commits, branches, and documentation.

## Purpose

Agent Core prevents the most common failure modes in AI-driven development: coding without a plan, committing without quality checks, and losing context across runs. It is the baseline contract that all 18 AID agents share.

## When Used

- Loaded automatically at the start of every run (the Run Start Protocol)
- Referenced by all role agents (architect, backend, frontend, QA, security, docs-writer, etc.)
- Invoked whenever an agent needs to determine its role, escalation path, or commit format
- Called by the Controller to enforce subagent workflow rules during EPIC execution

## Key Concepts

### Run Start Protocol v4.0

Every agent reads these files in order before doing any work:

1. `active-work.md` — current state, recent runs, blockers
2. `command-history.md` — known working commands
3. `lessons-learned.md` — gotchas and past lessons
4. `project-profile.yaml` — paths, conventions, and tech stack
5. Project context from `.aid-o/04-engine/memory/`
6. Task type determination (new task or continuation?)
7. Complexity assessment (is this an EPIC?)

After loading file-based context, agents optionally augment with Qdrant vector memory (if enabled) and knowledge context (if knowledge acquisition is configured).

### Role and Mindset Framework

Each task type maps to a specific role and mindset:

| Task Type | Role | Mindset |
|-----------|------|---------|
| Bug Fix | Detective | Root cause, not symptoms |
| New Feature | Architect then Builder | Design first, code second |
| Refactoring | Safety Officer | No behavior change |
| Exploration | Researcher | Multiple options and tradeoffs |
| Documentation | Technical Writer | Clear, concise, with examples |
| Epic Run | PM plus Dev | Track progress and dependencies |

### The 6 Absolute Rules

1. **Think-First** — propose a plan and wait for PM approval before implementing, except for trivial tasks
2. **Quality Gates before every commit** — all 6 gates must pass; see `quality-gates` skill
3. **Atomic commits** — one logical change per commit, format: `type(scope): description (YYYY-MM-DD HH:MM TZ)`
4. **Run file is source of truth** — create on approval, update after every commit, archive on completion
5. **Branch discipline** — always work in `run/YYYY-MM-DD-topic` branches, never commit to main without PM approval
6. **Run log always** — update the run log after every completion

### Subagent Workflow

When agents dispatch sub-agents (parallel or research tasks), the parent agent:
- Creates and manages the run file
- Coordinates all commits (sub-agents prepare, parent commits)
- Updates the run file after each sub-agent completes
- Runs quality gates before commit

Sub-agents must not commit independently or modify workspace files. They report results and flag discovered issues using a structured severity format (CRITICAL, HIGH, MEDIUM, INFO).

## How It Works

At run start, the agent loads context in the prescribed order, determines whether the task is a continuation or a new task, and assesses complexity. If the task warrants an EPIC (3+ runs), the agent proposes that to the PM before starting.

The agent then identifies its role, proposes a plan (writing it down), waits for PM approval, and only then creates a run file and branch. This think-first approach is enforced even when it feels slower — the plan catches scope mismatches before any code is written.

At the end of every agent output, a mandatory Execution Summary block records files read, files created, files modified, commands run, errors encountered, self-reported complexity, and the primary bottleneck. The Controller parses this for metrics and Qdrant storage.

## Configuration

Project configuration lives in `.aid-o/04-engine/memory/project-profile.yaml`, generated by `/aid-setup`. It defines:

- Branch prefix (default: `run/`)
- Commit format
- Run ID format: `R-{EPIC_ID}-{run_number}`
- Epic ID format: `E-{NNN}-{phase}_{total}`
- Standard `.aid-o/` directory structure

Skills are loaded on demand — agents load only the skills they need for the current task rather than loading all skills at startup.
