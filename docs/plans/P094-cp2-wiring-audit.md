## What the testbed found while this audit was written

The sabotaged-diff check `step_review_refuses_secret` (aid-testbed) came back
`skip` twice before it refused, and both times the step check was wrong, not
the fixture:

1. `yq … | @tsv` escapes the backslash of `\s` in `defaults/pre-filter-rules.yaml`,
   so every rule with a `\s` in it never matched. Read with `join("\t")` now.
2. The rules are written for `grep -E` and were applied with bash's POSIX `=~`
   (no `\s`), case-sensitively, so `AWS_SECRET_ACCESS_KEY = "…"` was not a
   secret. Applied with `grep -iE` now. Regression case in `test-step-check.bats`.

The P093 pre-filter had the same rules and applied them through grep, so this
was a regression of Step 3 that no unit test carried; the testbed's own
fixture did.
