# Design: Session File Detail Quality

**Date:** 2026-02-17
**Status:** Draft
**Scope:** AID Orchestrator plugin — session file creation (orchestrated + non-orchestrated)

---

## Problem

Session files created via `/run-epic` (orchestrated) and `/session-start` (non-orchestrated) are often sparse and insufficient. Plan JSON (generated by Planner skill) is detailed and schema-validated, but session files are lightweight templates that don't capture that detail. PM and agents need session files to be comprehensive operational documents.

### Root Cause

1. **Templates are too generic** — sections like "Objective", "Requirements" without explicit instructions on depth
2. **Instructions are vague** — `plan-epic.md` Step 5 says only "Generate phases from plan steps" with no further guidance
3. **No quality enforcement** — plan.json has schema validation, session files have none
4. **No explicit source list** — agent doesn't know WHERE to look for information to fill in detail

---

## Approach: Improved Templates + Explicit Instructions (Approach A)

Enhance existing mechanism — no new agents, no new skills, no schema. Better templates + clearer instructions + quality checklist.

---

## Session File Structure (Required Sections)

### Frontmatter

```yaml
id: S-{YYYYMMDD}-{4char-hash}
type: new-feature|bug-fix|refactoring|exploration
status: active|completed|blocked
priority: critical|high|medium|low
started: YYYY-MM-DD
# Orchestrated sessions add:
epic_id: {epic_id}
epic_session: N
plan_ref: path/to/plan.json
orchestrated: true
# Non-orchestrated:
orchestrated: false   # or omitted
```

### Required Sections (Both Flows)

1. **Objective** — What and why. Not "Implement X" but "Implement X because Y, which enables Z. Success = A, B, C." Min 3-5 sentences.

2. **Context** — Previous sessions, state of code, dependencies on other systems. Reference concrete files/commits.

3. **Scope** — Explicit IN/OUT lists. Min 3 items IN, min 2 items OUT. Prevents scope creep.

4. **Phases** — Core of session file. Each phase MUST contain:
   - **Goal** — what this phase solves (full paragraph)
   - **Agent/Role** — who works on it (from plan.json in orchestrated, Claude determines in non-orchestrated)
   - **Inputs** — files, context, outputs from previous phase
   - **Outputs** — files produced, artifacts, expected file paths
   - **Constraints** — allowed/forbidden paths, max changes, backward compatibility
   - **Acceptance** — checklist of how we know phase is done (min 3 items)

5. **Dependencies** — Which phases depend on which and why. Table or diagram.

6. **Quality Gates** — Which gates run after completion, what they verify.

7. **Session Log** — Timestamp + event table, updated progressively.

## Session Creation Protocol

### Orchestrated Flow (plan-epic.md Step 5)

**Sources agent MUST read BEFORE creating session file:**

1. **EPIC file** (`.aid-o/02-epics/{epic}.md`) — goal, scope, constraints, affected areas
2. **Plan JSON** (`plan.json`) — steps, dependencies, parallel_groups, analysis_groups, gates, budget
3. **Plan file** (`.aid-o/01-plans/` or `workspace/workflow/plans/`) — broader project context
4. **Previous session** (if exists) — context, what was done, lessons learned
5. **Relevant source code** — files mentioned in EPIC/Plan (inputs/outputs), to understand real state
6. **Decision policies** (`.aid-o/03-config/policies/decision-policies.yaml`) — auto_decisions, escalation_triggers

**Minimum detail per section:**

| Section | Minimum | Source |
|---------|---------|--------|
| Objective | 3-5 sentences: what, why, success criteria | EPIC goal + scope |
| Context | Previous sessions status, what's done, what's missing. Reference files/commits. | Previous session, git log |
| Scope | Explicit IN/OUT lists. Min 3 IN, min 2 OUT. | EPIC scope + constraints |
| Phases | Per phase: 1 paragraph goal, specific agent/role, input file list, output file list, constraints as bullets, acceptance checklist (min 3 items) | Plan JSON steps mapped 1:1 |
| Dependencies | Table: "Phase X depends on Phase Y because Z" | Plan JSON dependencies |
| Quality Gates | List of gates with description of what they verify | Plan JSON gates + decision-policies |
| Session Log | Initialize with "Session created" entry | -- |

**Plan JSON to Session Phases Mapping:**

```
For EACH step in plan.json:
  1. Read step.objective -> Phase goal (expand to full paragraph)
  2. Read step.role -> Phase agent/role
  3. Read step.inputs -> Phase inputs (translate paths to readable descriptions)
  4. Read step.outputs -> Phase outputs (descriptions + expected file paths)
  5. Read step.constraints -> Phase constraints
  6. Read step.allowed_paths + forbidden_paths -> Phase scope
  7. Check analysis_groups -- if step is target of analysis group, add note:
     "After completion: analysis review by {agents} ({mode})"
  8. Create acceptance checklist from outputs + constraints
```

### Non-Orchestrated Flow (session-start.md)

**Sources agent MUST read BEFORE creating session file:**

1. **`workspace/active-work.md`** — current project state
2. **EPIC file** (if exists — `.aid-o/02-epics/` or `workspace/workflow/epics/`) — gives scope and goal
3. **Plan file** (if exists) — broader project context
4. **User request / task description** — what PM wants
5. **Relevant source code** — files mentioned in task, to understand real state
6. **Previous sessions** (if relevant) — context

**Instructions for agent:**
- Don't just say "Implement feature X" — **analyze the task**, decompose into phases, identify who/what/how
- For each phase determine: what "type of work" it is (coding, testing, config, docs)
- If task spans multiple areas (backend + frontend + tests), each is a separate phase
- Always specify IN/OUT scope — what will change, what won't
- If scope is ambiguous, ask PM (AskUserQuestion) BEFORE creating session file
- If EPIC exists, use it as primary source for scope and goal (user request adds detail/priority)

## Files to Modify

### 1. `defaults/templates/session-new-feature.md` (+ bug-fix, refactoring, exploration)

Rework templates:
- Add **guidance comments** in each section (what belongs here, what detail level, examples)
- Add **required subsections** in Phases (goal, agent/role, inputs, outputs, constraints, acceptance)
- Add **min detail markers** — `<!-- MIN: 3-5 sentences -->` in Objective, `<!-- MIN: 3 items -->` in acceptance

### 2. `commands/plan-epic.md` Step 5

Expand from 5 lines to complete Session Creation Protocol:
- Sources agent must read
- Plan JSON to Session phases mapping (8-step process)
- Minimum detail per section (table)
- Quality checklist before saving

### 3. `skills/epic-orchestration.md` (PLANNING state)

Add:
- Reference to Session Creation Protocol
- Quality check: "Verify session file contains: filled Objective (3+ sentences), Scope IN/OUT, Phases with all subsections, Dependencies, Quality Gates"
- Transition condition: "Valid session file produced" (alongside existing "Valid Plan JSON produced")

### 4. `commands/session-start.md`

Expand instructions for non-orchestrated flow:
- Sources agent must read (including EPIC if exists)
- Instructions for task decomposition into phases
- Minimum detail per section
- "If task is ambiguous -> AskUserQuestion BEFORE creating session file"
